# Travel Diary

A private travel diary for Android. Add every city you have visited, watch the countries
light up on a world map, and keep notes about each trip. Everything stays on your phone.

## Features

- **World map home screen**: visited countries are highlighted and every place gets a pin.
  Drag, pinch or double-tap to zoom; the map wraps around the globe. Tap a country to see your
  places there or add one.
- **Center of gravity over time**: view your travels with a concept of time. A moving average
  (with configurable period: 30 days, 90 days, 180 days, 1 year, or all time) calculates your
  spherical center of gravity across time, drawing an animated line across the globe with interactive
  playback and scrubbing.
- **Offline city search**: about 34,000 cities are built in (every city above 15,000 people and
  every capital, including the smallest countries). Bigger lists with up to 236,000 towns and
  villages can be downloaded from [GeoNames](https://www.geonames.org) in Settings.
- **A diary for each place**: several visits per place, each with optional arrival and departure
  dates and notes. Browse them by country or on a timeline.
- **A photo for each place**: pick one from your gallery and it becomes the background of the
  place's page. The app keeps its own scaled-down copy, so deleting the original changes nothing.
- **Places that are not in any list**: long-press anywhere on the map to drop your own pin, for
  a national park, an island or a research station in Antarctica.
- **Statistics**: countries visited, share of the world's 195 countries, continents, travel days.
- **Backup**: export the whole diary to a JSON file and import it on another phone. Photos are
  not part of the export; they do move with Android's phone-to-phone transfer.
- **Private**: no account, no ads, no analytics. The app only connects to the internet when you
  download a bigger city list.
- Light and dark theme, English only for now.

## How it works

| Part | How |
| --- | --- |
| Language and UI | Kotlin, Jetpack Compose, Material 3 |
| Storage | Two local SQLite databases (Room): `diary.db` for your places and visits, `cities.db` for the city list, which can be replaced at any time without touching the diary |
| Photos | Picked with the system photo picker (no storage permission), then saved as a JPEG of at most 2048 px, turned upright, in the app's private `photos/` folder |
| Map | Drawn on a Compose `Canvas` from the bundled country shapes (Miller projection), so no map tiles, API key or network are needed |
| City search | Accent-insensitive prefix search over the local city list: "zurich", "Zürich" and "Zuerich" all work |
| Downloads | Settings > City database downloads `citiesXXXX.zip` straight from `download.geonames.org` and imports it in one transaction |

The bundled data in `app/src/main/assets` is generated by `tools/build_assets.py`
(standard library only):

```sh
python3 tools/build_assets.py --raw /tmp/travel-diary-raw --out app/src/main/assets --download
```

Natural Earth draws some borders as they are on the ground, while GeoNames and ISO 3166 use the
internationally recognised ones. The script aligns the map with the city list, so that a city
always highlights the country it belongs to: French overseas regions, Svalbard, Caribbean
Netherlands, Tokelau, Christmas and Cocos Islands become their own countries, Crimea is part of
Ukraine and Western Sahara is separate from Morocco.

## Development

You need JDK 17 or newer (21 recommended) and the Android SDK, which Android Studio installs.
Open the folder in Android Studio, or use the command line:

```sh
./gradlew assembleDebug        # app/build/outputs/apk/debug/app-debug.apk
./gradlew testDebugUnitTest    # unit tests, including database tests with Robolectric
./gradlew lintDebug
```

```
app/src/main/java/app/traveldiary/
  data/cities/     city list: Room database, GeoNames parser, downloads, search
  data/diary/      your places, visits and photos, JSON backup
  data/countries/  country names, continents, flags
  data/stats/      statistics
  map/             projection, country shapes, the zoomable map composable
  ui/              one package per screen (map, search, editor, place, places, stats, settings)
tools/build_assets.py           regenerates the bundled map and city data
scripts/create-release-key.sh   creates the release signing key
```

## Releasing

Every release is built by GitHub Actions and signed with your release key. Obtainium (like
Android itself) only accepts an update signed with the same key as the installed app.

### One-time setup

1. Create the signing key:

   ```sh
   scripts/create-release-key.sh ~/travel-diary-release.jks
   ```

2. Add the four secrets it lists (`KEYSTORE_BASE64`, `KEYSTORE_PASSWORD`, `KEY_ALIAS`,
   `KEY_PASSWORD`) in the repository's **Settings > Secrets and variables > Actions**.
3. Back up the `.jks` file and its password, for example in a password manager. If they are lost,
   installed apps can no longer be updated and everyone has to reinstall.

### Publishing a version

```sh
git tag v1.0.0
git push origin v1.0.0
```

The [Release workflow](.github/workflows/release.yml) runs the tests, builds the APK with the
version taken from the tag and publishes `travel-diary-1.0.0.apk` as a GitHub release. Obtainium
picks it up from there. Tags must look like `v1.2.3` and always go up: the Android version code
is derived from them (`v1.2.3` becomes 10203).

To build a signed APK on your own machine, create a `keystore.properties` file in the project
folder (it is ignored by git):

```properties
storeFile=/home/you/travel-diary-release.jks
storePassword=...
keyAlias=travel-diary
keyPassword=...
```

and run `./gradlew assembleRelease -PappVersion=1.0.0`.
